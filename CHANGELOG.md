## [Unreleased]

## [2.2.1] - 2026-10-20

### Fixed
- Проверка аккаунтов больше не запускается при каждом возвращении фокуса в ShotShorts. Обновление выполняется явно; временные окна и вкладки закрываются, скрытые дубликаты профилей не проверяются повторно.
- Ручной вход в TikTok открывается в обычном установленном браузере без подключения Playwright. Пока окно входа работает, чтение аккаунта, статистика этого профиля и загрузка блокируются, чтобы не конфликтовать за профиль.
- Закрытие окна входа определяется по фактическому процессу браузера и точному пути профиля, включая передачу профиля другому процессу и перезапуск ShotShorts.
- Чтение статистики ожидает завершения текущей отправки и закрывает только свою временную вкладку. Ошибка обновления сохраняет предыдущие данные; неизвестные счётчики не заменяются нулями. Разбор учитывает выравнивание заголовков и чисел в Studio.

### Added
- Выбор Microsoft Edge или Google Chrome для нового аккаунта с сохранением браузера между запусками. Старые профили продолжают использовать Edge; перенос cookies между браузерами не выполняется.
- Статистика TikTok по выбранному аккаунту: просмотры, лайки, комментарии и время обновления. Снимок охватывает только текущую страницу списка Studio, а не всю историю канала.
- Кнопка «Сохранить и применить время ко всем черновикам»: распределение по первой дате и интервалу с пропуском занятых слотов, без изменения описаний и остальных настроек.
- Необязательное автоматическое удаление карточек после подтверждённой загрузки. Видео на диске и в TikTok сохраняются; история завершённых загрузок предотвращает повторное добавление файлов и сохраняет последовательность временных слотов.


## [2.2.0] - 2026-10-20

### Added
- Несколько аккаунтов TikTok Studio с отдельными профилями Edge, пресеты описаний и случайные уникальные хештеги. Готовые клипы добавляются в план сразу после рендера каждого файла; локальные записи можно удалять без удаления видео и публикаций.
- Зелёный хромакей баннера в превью и рендере Stories/Cinema, включая вставки с паузой.
- Статический сайт с условиями использования и политикой конфиденциальности, карта проекта и CI для unit-тестов.
- **План публикаций TikTok**: результаты генерации автоматически добавляются в постоянную очередь с отдельным временем и настройками каждого ролика. Общий шаблон назначает последовательные слоты, описание, видимость и разрешения. При явном включении автозагрузки новые клипы передаются заранее в нативное расписание TikTok Studio через отдельный профиль Edge; ключи разработчика для этого способа не нужны. Неоднозначные отправки останавливают очередь и требуют проверки, чтобы избежать дубликатов.
- Вкладка **TikTok** также поддерживает отдельную немедленную публикацию через Direct Post API: OAuth Desktop с PKCE, описание, видимость, разрешения комментариев/дуэтов/сшивания, маркировка ИИ и рекламы, отправка и проверка статуса. Ключи и токены шифруются средствами ОС; публичная публикация через этот API требует аудита TikTok.
- **СДВГ-ролик параллельно фильму (режим кино)** — чекбокс «СДВГ-ролик параллельно» в секции «Режим кино» добавляет на вертикальный кадр второй слой: отрывок фильма и случайные ролики из папки фоновых видео идут одновременно, каждый в своём прямоугольнике. Раскладка настраивается как у баннера: оба прямоугольника перетаскиваются и растягиваются за ручки в живом превью (крайние ручки — ширина/высота независимо, угловая — обе оси сразу, без фиксации пропорций), есть невидимые направляющие по центру/краям кадра, минимальная видимая часть 10px и кнопка «Сбросить раскладку» (по умолчанию фильм сверху, СДВГ снизу, пополам 1080x960). Дополнительно выбираются: порядок слоёв (фильм поверх СДВГ или наоборот), заполнение пустого места кадра (чёрный / размытый кадр фильма / размытый СДВГ-кадр) и размеры сторон в пикселях; настройка «Вертикальный кадр» при этом применяется внутри прямоугольника фильма. СДВГ-ролики сменяют друг друга случайно без повторов подряд и играют без звука — звук остаётся только у фильма; если роликов в папке меньше, чем длительность сцены, один ролик зацикливается, а при сбое декодирования цепочки рендер повторяется с одним зацикленным роликом. Папка фоновых видео становится обязательной в режиме кино с включённым слоем (кнопка Generate и главный процесс проверяют её), все новые настройки входят в пресеты. Режим баннера не менялся; бонусом исправлено перетаскивание баннера в превью при выключенных субтитрах (`cinema-bg-utils.js`, `buildCinemaBgFilterGraph`, `selectBackgroundVideos` выделен в общий метод со Stories-фоном)
- **Экран ревью сцен в режиме кино** — перед рендером пайплайн останавливается и показывает карточки выбранных сцен: превью-кадр, название, хук, бейдж источника (диалог/экшн), таймкоды и длительность. Сцену можно исключить галочкой или подвинуть её границы (поля start/end в секундах), после чего рендер запускается кнопкой «Рендерить выбранные» только по подтверждённым сценам; «Отменить прогон» полностью останавливает выполнение без рендера. Настройка «Просмотр сцен перед рендером» в секции «Режим кино» отключает экран и возвращает прежний one-click режим; отмена на этапе ревью работает и через общую кнопку Cancel. Отключённые при ревью временные файлы превью удаляются сразу (`requestSceneReview`/`applySceneEdits` в `cinema-scene-detector.js`, IPC `cinema:reviewDecision`)
- **Снап начал диалоговых сцен к склейкам** — энергетический проход (ebur128 + scdet) теперь выполняется для каждого кино-прогона, и начала сцен, найденных LLM по диалогам, привязываются к ближайшей визуальной склейке фильма (до 2 сек назад), чтобы клипы не открывались посреди кадра; снап не допускает пересечения с предыдущей сценой и не трогает конец сцены (`snapDialogueSceneStart`)
- **Длина action-окон из настроек** — action-детектор использует целевую длину сцены из настроек режима кино (клампится в 8–90 сек) вместо жёстких 15 сек; без настроек остаётся прежнее поведение
- **Заголовки и хуки для action-сцен через LLM** — когда внутри action-сцены достаточно речи (≥ 40 символов транскрипта), модель генерирует для неё название и хук вместо плейсхолдера «Action N»; сцены без речи и сбои вызова оставляют fallback без остановки пайплайна (`titleActionScenes`, `SYSTEM_TITLE_ACTION`)
- Сцены в кино-списке перенумеровываются хронологически: ревью-экран, метаданные клипов и правки границ используют стабильные порядковые номера
### Fixed
- TikTok Studio дожидается завершения загрузки и обработки видео, проверяет доступность кнопки планирования и повторно считывает настройки перед отправкой.
- Последовательная загрузка нескольких роликов открывает новую форму через навигацию Studio с запасным прямым переходом. Расписание подтверждается только по записи нужного ролика с датой и временем; поддерживаются отложенные метаданные и компактные русские даты.
- Исправлены выбор видимости, взаимодействие со списком времени и раскрытие дополнительных настроек под закреплённой панелью. Поддержаны окна подтверждения отправки.
- Проверка аккаунта использует точный логин TikTok; при несовпадении интерфейс показывает ожидаемый и обнаруженный аккаунты.
- Если TikTok заблокировал повторное использование контента в выключенном состоянии, отправка продолжается с предупреждением и выключенным повторным использованием.
## [2.1.0] - 2026-09-09

### Added
- **Релизы GitHub** — новый workflow `.github/workflows/release.yml` собирает portable `.exe` на Windows-раннере и публикует GitHub Release с версией программы и заметками из этого changelog. Релиз запускается пушем тега `v*` (например `git push origin v2.1.0`); FFmpeg для сборки скачивается автоматически, так что собранный exe самодостаточен
- **Настраиваемая длина роликов** — в настройках появились секции «Stories Mode» и «Cinema Mode» с управлением длиной. **Истории:** целевой диапазон (мин/макс) управляет объединением коротких и нарезкой длинных историй, жёсткие границы форсируют крайние случаи (короче жёсткого минимума — принудительное слияние, длиннее жёсткого максимума — нарезка по завершённым фразам; если безопасного разреза нет, история остаётся целиком). Цепочка значений автоматически поддерживается: жёсткий мин ≤ целевой мин ≤ целевой макс ≤ жёсткий макс. **Кино:** мин/целевая/макс длина сцены — это подсказка для ИИ в промпте (LENGTH GUIDANCE в user-сообщении; system-контракт остаётся без хинтов о длине), пайплайн больше никогда не режет и не склеивает сцены; чекбокс «Ограничивать макс. длину» позволяет полностью отключить верхний предел. Все значения входят в пресеты
- **Интерстишл-режим баннера** — режим «Pause video & play banner with sound»: через каждые N секунд ролик ставится на паузу (стоп-кадр + тишина), поверх проигрывается видео-баннер **со своим звуком**, затем контент продолжается с места паузы. Длительность паузы равна **длительности самого видео-баннера** (настройка не нужна), клип удлиняется на суммарное время пауз; субтитры сдвигаются по таймлайну, а те, что пересекают начало паузы, обрезаются ровно в момент появления баннера; работает в обоих путях рендера — основном (concat) и фолбэке (loop одного фона) (`planInterstitialSegments` / `buildInterstitialFilterGraph` в `banner-utils.js`)
- **Цепочки фолбэков моделей** — для транскрибации и анализа собираются упорядоченные цепочки: если модель упёрлась в rate limits или её ключ/ID отвергнут (429/401/403/404), следующая модель в цепочке подхватывает автоматически, переключение «липкое» и действует до конца запуска, в том числе между чанками длинного аудио
- **Провайдеры с общим ключом** — секция «Custom AI Models» разделена на три шага: провайдер (Base URL + API ключ) → модели (привязаны к провайдеру, сколько угодно моделей на один ключ) → цепочки фолбэков (добавление, перемещение ↑↓, удаление). Старые настройки с моделями «каждая со своим ключом» мигрируют автоматически, одиночные выборы моделей становятся цепочками из одного элемента

### Changed
- **Секции моделей сворачиваются** — «Providers», «Models» и «Fallback chains» в настройках складываются/разворачиваются кликом по заголовку, состояние запоминается между сессиями; в заголовках списков отображается количество записей
- **Цепочки в два столбца** — каждая запись цепочки показывает название провайдера и имя модели (без технического ID) в двух колонках: при сжатии окна текст обрезается с многоточием, при растяжении остаётся свободное место; селекторы цепочек тоже показывают только имена моделей
- **Переработаны промпты анализа историй** — контракт вынесен в system-роль (её раньше не было), user-сообщение несёт только данные (core range, таймкоды, блоки). Промпт объясняет цель (standalone вертикальные клипы), требует группировать мини-анекдоты одной темы в одну дугу и включает самопроверку перед выводом; длительность историй промптом не задаётся — разделение по 1:30/5:00 остаётся заботой системы компоновки. Убраны стилистические примеры границ
- Исправлено: склеенные клипы называются по **первой** истории вместо «Тема A + Тема B»
- **Убран раздел «Groq API Keys»** — кастомные модели стали единственным способом подключить AI: любой OpenAI-совместимый провайдер (включая Groq — просто добавь `https://api.groq.com/openai/v1` как Base URL). Селекторы транскрибации и анализа больше не содержат встроенных моделей; генерация требует собранные цепочки транскрибации и анализа
- Исправлено: кнопки «Добавить» в цепочках транскрибации/анализа не активировались при выборе модели в выпадающем списке (не было обработчика `change` на селекте)
- Очистка настроек: из хранилища удалены `apiKeys`, `groqApiKey` и `apiProvider`; старые значения игнорируются, модельные выборы сбрасываются на пустые
- **Свободная позиция субтитров** — текст перетаскивается прямо в живом превью как баннер: невидимые точки-фиксаторы по центру и краям обеих осей, угловая точка масштабирует текст пропорционально (обе оси сразу, без искажений). В рендере позиция ставится через ASS `\pos()` с центр-анкором; классические «Позиция/Отступ» при этом игнорируются
- **Рекламный баннер** — поверх каждого клипа можно наложить фото или видео **любого формата** (mp4, mov, webm, mkv, avi, wmv, flv, ts, 3gp, gif и т. д.; видео зацикливается автоматически, поворот из метаданных телефона учитывается). Видео-баннеры перед рендером нормализуются в чистый промежуточный файл (поворот, 30fps, чётные размеры, без аудио) — edit lists, VFR и экзотические кодеки больше не ломают воспроизведение; источники с альфа-каналом (ProRes 4444, VP9 alpha) идут напрямую с сохранением прозрачности. Позиция и размер задаются перетаскиванием в общем живом превью 1080x1920 вместе с субтитрами: боковые точки растягивают по осям по отдельности, угловая — масштабирует пропорционально без искажений (точки появляются при наведении), баннер можно выдвигать за край кадра, невидимые полоски-направляющие «прилипают» баннер к краям и центру по обеим осям, слайдер «Видимость» делает баннер полупрозрачным или полностью невидимым, кнопка «Сбросить» возвращает исходное положение. Настройки сохраняются и входят в пресеты (`banner-utils.js`, IPC `media:probe`, секция «Ad Banner» в настройках)
- **Нарезка и склейка историй** — модули `story-chunker` и `story-padding`: объединение соседних коротких историй (пороги настраиваются в секции «Stories Mode»), разделение длинных только по границам сегментов транскрипта, привязка краёв клипов к естественным паузам речи
- **Плавная чёткость превью** — новый селектор sharpness в интерфейсе (`renderer/sharp-select.js`)
- Расширено покрытие тестами: story-chunker, story-padding, groq-story-analyzer

### Fixed
- **Portable-сборка без Playwright в рантайме** — `playwright` перенесён в `devDependencies` и подключается лениво в `subtitle-renderer.js`: модуль больше не падает при импорте, если пакета нет в продакшн-сборке, а деградирует до фолбэка на ASS-субтитры с понятной ошибкой при попытке запустить Chromium
- В сборку Electron добавлены только нужные языки (`en-US`, `ru`) — portable exe стал заметно легче

### Removed
- Экспериментальная поддержка OpenRouter и NVIDIA NIM удалена — клиенты `base-audio-client.js`, `openrouter-client.js` и `nvidia-client.js` больше не поставляются. Пайплайн снова работает только через **Groq** (Whisper для транскрибации + Qwen для анализа)
