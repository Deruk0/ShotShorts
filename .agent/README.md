# Карта проекта ShotShorts

## Назначение и стек

ShotShorts — настольное Windows-приложение для создания вертикальных роликов из длинных видео и аудио. Основные режимы: Stories и Cinema. Приложение использует Electron, JavaScript с CommonJS, обычные HTML/CSS и FFmpeg через `fluent-ffmpeg`. Настройки хранятся через `electron-store`.

Корневой npm-проект содержит workspace `app`. Версии и зависимости следует проверять в `package.json` и `app/package.json`. README указывает Node.js 20+, CI использует Node.js 22.

## Точки входа и границы

| Путь | Назначение |
| --- | --- |
| `app/launch.js` | Запуск Electron из npm-скрипта. |
| `app/main.js` | Главное окно, жизненный цикл приложения, IPC настроек, статистики, диалогов и информации о медиа. |
| `app/preload.js` | Мост `window.api` между renderer и главным процессом. |
| `app/renderer/index.html` | Разметка интерфейса. |
| `app/renderer/app.js` | Поведение интерфейса, настройки, превью, управление обработкой и показ прогресса. |
| `app/renderer/styles.css` | Стили интерфейса. |
| `app/renderer/sharp-select.js` | Пользовательские элементы выбора. |
| `app/services/process-handler.js` | Координация Stories/Cinema, запуск, отмена, прогресс и подтверждение сцен. |
| `app/services/tiktok-service.js` | OAuth Desktop с PKCE, шифрованное хранение ключей, обновление токенов, Direct Post и проверка статуса. |
| `app/services/tiktok-ipc.js` | Проверяемые IPC-обработчики TikTok, ffprobe и открытие браузера для авторизации. |
| `app/renderer/tiktok.js` | Вкладка TikTok: подключение аккаунта, выбор ролика, описание, разрешения, согласие и статус. |
| `app/services/tiktok-captions.js` | Подстановка команд в описания и случайный выбор хештегов из проверенных пресетов. |
| `app/services/tiktok-queue.js` | Постоянная очередь готовых клипов, шаблон временных слотов и настроек, последовательная отправка и восстановление после сбоя. |
| `app/services/tiktok-login-browser.js` | Запуск установленного Chrome или Edge для ручного входа без Playwright и remote debugging; отслеживание закрытия окна по реальному процессу с точным `--user-data-dir`. |
| `app/services/tiktok-studio.js` | Управление отдельным профилем Edge или Chrome через Playwright: заполнение реальной формы TikTok Studio, проверка настроек и передача в нативное расписание. |
| `app/services/tiktok-statistics.js` | Чтение видимых счётчиков списка Studio, разбор чисел и сохранение статистики по аккаунтам. |
| `app/renderer/tiktok-queue.js` | План публикаций: общие настройки новых клипов и индивидуальное редактирование каждого ролика. |

Renderer работает с `contextIsolation: true` и `nodeIntegration: false`. Доступ к Node.js и системным операциям проходит через preload и IPC. При изменении контракта проверяйте вместе `renderer/app.js`, `preload.js`, `main.js` и `process-handler.js`.

Основные каналы обработки: `process:start`, `process:cancel`, `process:progress`, `cinema:reviewDecision`.

TikTok поддерживает два разных пути. Разовая немедленная отправка через Direct Post использует `tiktok:*`, собственное приложение TikTok с `video.publish` и зашифрованный файл `tiktok-credentials.enc`; для публичных публикаций через этот API требуется аудит. Ключи и токены не входят в `settings:get` и не встраиваются в EXE.

План публикаций использует `tiktok:queue:*` и нативное расписание TikTok Studio, доступное в браузерной форме. Для нового аккаунта интерфейс позволяет выбрать Microsoft Edge или Google Chrome. Браузер сохраняется в поле `browser` записи аккаунта и используется при повторном открытии и отправке; старые записи без поля используют Edge. Незавершённый вход повторно используется только для того же браузера. Смена браузера создаёт отдельный профиль и требует нового входа; cookies не переносятся. Playwright является runtime-зависимостью и запускает установленный браузер с отдельным профилем `userData/tiktok-studio-profile`. Кнопки входа запускают установленный браузер обычным процессом через `tiktok-login-browser.js`, без подключения Playwright, remote debugging и флагов автоматизации. Перед ручным входом управляемый контекст этого профиля закрывается. Пользователь входит в TikTok самостоятельно, закрывает все окна этого профиля и нажимает «Обновить аккаунты». Edge и Chrome могут передать профиль другому процессу и завершить исходный launcher. Поэтому закрытие ручного окна определяется по фактическому процессу браузера с точным путём профиля через Windows CIM, включая окна от предыдущего запуска программы. Ошибка чтения процессов блокирует повторный запуск с `studio_browser_state_unavailable`. Пока процесс входа работает, чтение аккаунтов, статистики этого профиля и отправка блокируются с `studio_login_window_open`. После закрытия Playwright использует тот же профиль с сохранённой сессией TikTok. При выходе из программы окно ручного входа не закрывается принудительно; перед следующим запуском его нужно закрыть самостоятельно. Первый аккаунт сохраняет прежний профиль; дополнительные аккаунты используют отдельные профили `userData/tiktok-studio-accounts/<id>`. Файл `userData/tiktok-studio-accounts.json` хранит идентификаторы профилей, выбранный браузер и определённые в Studio публичные имена аккаунтов. Пароли и cookies остаются в профилях браузера. IPC `tiktok:studio:accounts`, `refreshAccounts`, `addAccount` и `open` обслуживают список и вход. Обновление списка проверяет сохранённые профили через отдельную временную страницу Studio в том же браузерном контексте. Имя считывается из `commonAppContext.user.uniqueId` в HTML-экранированном `__Creator_Center_Context__`, доступном до выбора видео; точный `uniqueId` имеет приоритет над видимым именем в форме, которое используется только при отсутствии читаемого `uniqueId`. При несовпадении аккаунта очередь сохраняет `accountCheck` с ожидаемым и обнаруженным публичными логинами и этапом проверки; UI показывает оба логина. Временная страница закрывается после проверки и не загружает видео. Это также учитывает вход в другой вкладке и повторно открывает закрытые сессии. Одинаковые имена аккаунтов и пустые записи объединяются только при отображении; профили и сохранённые входы не удаляются. Незавершённый вход, включая исходный профиль, повторно используется при добавлении аккаунта. Проверка входа запускается только кнопкой «Обновить аккаунты»: возвращение фокуса в программу не открывает браузер. Проверяются только отображаемые профили, без скрытых дубликатов. Если для проверки создаётся отдельный браузерный контекст, используется его начальная пустая вкладка, а весь контекст закрывается в `finally`, в том числе при ошибке. В уже открытом контексте закрывается только временная вкладка проверки; окно загрузки сохраняется. Выбранное имя сохраняется в шаблоне и отдельно у каждого ролика; драйвер открывает соответствующий профиль и повторно проверяет аккаунт перед отправкой. Очередь и шаблон хранятся в `userData/tiktok-queue.json`; каждый элемент содержит свой аккаунт, файл, описание, дату в ISO UTC и настройки. UI и браузер используют часовой пояс компьютера. Модуль `process-handler` вызывает `onGenerated` после каждого успешно отрендеренного клипа Stories/Cinema, до запуска следующего. Поэтому отмена или ошибка дальнейшего рендера не скрывает уже готовые ролики. В пределах запуска успешно добавленные файлы повторно не отправляются; неудавшиеся записи очереди повторяются при следующем клипе и завершении. Ошибка очереди не превращает успешно отрендеренные ролики в ошибку генерации. Автозагрузка новых роликов включается только явным сохранением соответствующей настройки.

Пресеты описаний и хештегов сохраняются в том же `tiktok-queue.json` в массивах `captionPresets` и `hashtagPresets`. Старые очереди без этих полей получают пустую библиотеку. Шаблон новых клипов содержит текст описания и `hashtagPresetId`. Команды: `{name}` — имя файла без расширения, `{filename}` — с расширением, `{n}` — номер в плане, `{hashtags}` — случайная выборка хештегов. Остальной текст сохраняется; если команда `{hashtags}` отсутствует, выбранные хештеги добавляются в конец. Выборка содержит случайное количество уникальных тегов в заданном диапазоне и случайный порядок; при малом наборе используются все доступные теги. Итог проверяется по ограничению описания в 2200 единиц UTF-16 и сохраняется у ролика один раз, поэтому обновление интерфейса, перезапуск и повторная отправка не меняют его. Для существующего черновика сборка выполняется явно в его редакторе с последующим сохранением. Изменение или удаление пресетов не переписывает готовые описания. Методы `tiktok:queue:previewCaption`, `saveCaptionPreset`, `saveHashtagPreset`, `removeCaptionPreset`, `removeHashtagPreset` работают через проверенный IPC.

Кнопка «Сохранить и применить время ко всем черновикам» вызывает существующий `tiktok:queue:template` с `applySchedule: true`. В одной транзакции сохраняется шаблон, а у всех `draft` распределяются времена по первой дате и интервалу, в порядке списка. Слоты остальных статусов и автоматически убранных загруженных роликов пропускаются. Дата должна быть минимум через 15 минут с шагом 5 минут. Неверный ввод не меняет ни шаблон, ни ролики. Описания, аккаунты, разрешения и статусы существующих роликов не переписываются; массовое изменение времени само по себе не запускает отправку. Обычное сохранение шаблона по-прежнему применяется только к новым роликам.

Раздел «Статистика TikTok» использует IPC `tiktok:statistics:get/refresh` и отдельный файл `userData/tiktok-statistics.json`. Пользователь выбирает сохранённый аккаунт и нажимает «Обновить статистику». Драйвер ожидает завершения активной отправки, открывает отдельную временную вкладку списка публикаций в том же профиле, проверяет аккаунт и считывает описания, просмотры, лайки и комментарии. Вкладка закрывается в `finally`, страница загрузки не меняется. Следующая отправка ожидает окончания чтения. Снимок содержит дату обновления и только текущую страницу списка Studio (`scope: content_page`); это явно указано в интерфейсе, перехода по всей истории пока нет. Неизвестные счётчики не превращаются в нули; ошибка чтения не перезаписывает предыдущий снимок. Пароли и cookies в снимок не входят. Тесты: `tiktok-statistics.test.js`, `node test/tiktok-statistics-smoke.cjs` (локальный макет без запросов в TikTok), `node test/tiktok-ui-smoke.cjs`.

Если браузер запущен только для статистики, список открывается сразу и весь созданный контекст закрывается после чтения, без промежуточной страницы загрузки. Уже существующий контекст сохраняется; закрывается только временная вкладка. Столбцы определяются по ячейкам заголовков либо промежуткам между их центрами, а не по левому краю текста: различное выравнивание подписей и чисел не должно скрывать строки. При сбое `userData/tiktok-statistics-diagnostic.json` сохраняет этап (`browser`, `navigation`, `account`, `counters`), адрес без query, количество найденных заголовков, числовых элементов и строк, а также границы столбцов. Описания роликов, HTML, cookies и пароли в этот отчёт не записываются.

Не помечайте ролик запланированным до подтверждения результата в Studio. Незавершённые при перезапуске и неоднозначные отправки требуют ручной проверки и не повторяются автоматически. Вход, CAPTCHA, изменившиеся поля и недоступные настройки должны останавливать отправку, а не обходиться. Исключение по запросу пользователя: если TikTok заблокировал повторное использование в выключенном состоянии, драйвер оставляет его выключенным и продолжает отправку. Остальные настройки проверяются как прежде. После подтверждения расписания ограничение сохраняется в `receipt.warnings` и отображается у ролика; исходные настройки шаблона и плана не переписываются. Коммерческая маркировка доступна в отдельной форме Direct Post, но не в текущем браузерном адаптере очереди.

После выбора файла драйвер ожидает готовности формы до 30 минут: незавершённые индикаторы загрузки и обработки должны исчезнуть, описание должно стать доступным для редактирования, а кнопка публикации должна присутствовать в форме. До заполнения настроек кнопка может быть неактивной; это не мешает начать заполнение. Готовое состояние должно сохраняться 2 секунды. После настройки ролика драйвер отдельно ждёт доступности кнопки «Запланировать» до 30 минут и повторно считывает настройки. Перед отправкой должны отсутствовать индикаторы загрузки и обработки, а кнопка должна оставаться активной 1 секунду. Оба ожидания отменяются через AbortSignal; тайм-ауты отображаются отдельными ошибками.

Раскрытие дополнительных настроек учитывает закреплённую панель публикации: после прокрутки к центру обычное нажатие ограничено 2 секундами. Если панель перекрывает элемент, драйвер вызывает DOM-обработчик только у однозначно найденного «Показать больше» и проверяет появление «Показать меньше» и переключателя ИИ. Для отключённых элементов, переключателей, согласия и финальной отправки этот запасной путь не используется.

Перед ожиданием активности «Запланировать» драйвер прокручивает кнопку в область просмотра, включая вложенные прокручиваемые панели. После обычного нажатия он ожидает переход в список публикаций либо распознаваемое окно подтверждения планирования или публикации. Кнопка подтверждения выбирается только внутри этого окна и нажимается один раз; неизвестное окно требует ручной проверки. Успех по-прежнему определяется записью ролика с нужными датой и временем в списке Studio, а не закрытием окна или самим нажатием.

Поддерживается показанное пользователем окно «Продолжить публикацию?» о незавершённой проверке авторских прав: драйвер нажимает «Опубликовать» внутри него. Это подтверждение прекращает проверку, как указано в самом окне; ожидание загрузки видео и проверка записи в расписании сохраняются.

После перехода в список Studio драйвер до 30 секунд ожидает полную запись расписания: описание может появиться раньше даты и статуса. Длительность на миниатюре не считается временем публикации. Проверка не выходит за границу строки таблицы или списка и поддерживает числовую русскую дату наряду с ISO и краткой датой месяца. Только подтверждённая запись переводит ролик в `scheduled`, после чего очередь автоматически берёт следующий `ready`. Браузерный smoke проверяет этот переход на двух роликах с разными временами, задержкой метаданных и длительностью рядом с описанием.

Для следующего ролика драйвер на странице списка публикаций нажимает видимую кнопку или ссылку «Загрузить» (`Upload`), ожидает перехода в форму и появления поля выбора файла. Это сбрасывает форму через навигацию самого Studio. Первая загрузка по-прежнему открывается по прямому адресу. Smoke дополнительно проверяет, что второй ролик проходит именно через кнопку списка.

Если свёрнутый элемент не имеет доступной ссылки или названия либо нажатие не открывает форму за 3 секунды, драйвер переходит на известный адрес загрузки напрямую. Запасной переход выполняется до выбора следующего файла и не повторяет отправку предыдущего ролика. Ошибки перехода и отсутствия поля выбора файла различаются: `studio_upload_navigation_timeout` и `studio_file_input_timeout`. Smoke проверяет три последовательных ролика: переход через ссылку со значком и переход напрямую при безымянном `div` в боковой панели.

В свёрнутой боковой панели элемент загрузки может содержать только значок «+». Драйвер сначала ищет видимую ссылку на `/tiktokstudio/upload`, затем использует текстовые названия. Компактная метка расписания вида «20 окт, 23:00» не содержит слова «Запланировано»; точные будущие дата и время в строке нужного ролика также подтверждают расписание. Разделительные запятые и точки в сокращениях месяца нормализуются. Smoke проверяет два ролика с такими метками и безымянной ссылкой со значком.

Кнопка «Убрать из плана» удаляет только локальную запись: файл и публикация в TikTok сохраняются. Удаление доступно для черновиков, ожидающих загрузки, запланированных роликов и записей с ошибкой; активно загружаемый ролик удалять нельзя. Удаление само по себе не возобновляет остановленную очередь.

Переключатель «Автоматически убирать из списка после подтверждённой загрузки в TikTok» сохраняется независимо от шаблона через `tiktok:queue:preferences`, по умолчанию выключен и применяется к следующим загрузкам. После подтверждённого ответа Studio очередь убирает карточку, сохраняя только путь и время в `completedUploads` для защиты от повторного добавления того же файла и сохранения временных слотов. Ошибки и неоднозначные результаты остаются в списке. Файлы на диске и ролики в TikTok не удаляются; существующие карточки не очищаются при включении переключателя.

«Открыть видео» доступно у каждой карточки и открывает файл в системном видеоплеере. IPC `tiktok:queue:openVideo` принимает идентификатор записи, проверяет отправителя, существование файла и расширение видео; произвольный путь из renderer не принимается. Перемещённый или удалённый файл показывает понятную ошибку. Эти сценарии и сохранение настройки проверяются `node test/tiktok-ui-smoke.cjs`. Передача клипов Cinema в общий план покрыта `process-generated.test.js`: успешный рендер, ошибка и отмена последующего рендера.

## Обработка медиа и AI

Общий путь: выбор исходника → извлечение и подготовка аудио → транскрибация → анализ текста и выбор фрагментов → подготовка границ и оформления → рендер клипов. Cinema дополнительно использует анализ сцен и диалог их подтверждения.

| Модуль в `app/services/` | Ответственность |
| --- | --- |
| `media-processor.js` | FFmpeg, обработка медиа и сборка выходных видео. |
| `whisper-service.js` | Транскрибация, работа с таймкодами и формирование ASS-субтитров. |
| `groq-story-analyzer.js` | LLM-анализ историй и сцен, уточнение границ. |
| `model-registry.js` | Провайдеры, модели, нормализация, миграция старых настроек и цепочки моделей. |
| `groq-key-utils.js` | Нормализация ключей и ожидание доступного ключа. |
| `story-chunker.js` | Разбиение транскрипта и заполнение разрывов таймлайна. |
| `story-padding.js` | Согласование границ историй с транскриптом. |
| `cinema-scene-detector.js` | Анализ энергии фильма, подбор и нормализация сцен, применение правок. |
| `cinema-bg-utils.js` | Геометрия и FFmpeg-фильтры параллельного фона Cinema. |
| `banner-utils.js` | Геометрия баннеров, фильтры наложения и вставок с паузой, общий фильтр зелёного хромакея для рендера и превью. |
| `subtitle-renderer.js` | Дополнительный рендер субтитров с использованием Playwright/Chromium; проверяйте места вызова перед изменением. |
| `font-manager.js` | Получение и подготовка шрифтов. |
| `cancellation.js` | AbortSignal, отменяемые ожидания и остановка FFmpeg. |
| `store.js` | Схема, значения по умолчанию, чтение и сохранение настроек, прокси и статистики. |
| `cleanup.js` | Очистка временных файлов приложения. |

Настройка баннера `bannerChromaKey` включает автоматическое удаление зелёного цвета в превью и при рендере Stories/Cinema, включая вставки с паузой. По умолчанию выключена для совместимости; применяется ко всем зелёным деталям баннера. Проверка фильтра и реального MP4: `node --test test/banner-chroma.test.js` (FFmpeg-проверка требует `app/resources/ffmpeg.exe`). Интерфейс, сохранение настройки и прозрачность превью в изолированном Electron: `node test/banner-ui-smoke.cjs`.

Имена `GroqStoryAnalyzer` и `WhisperService` исторические: подключение моделей поддерживает настраиваемые OpenAI-совместимые провайдеры. Не считайте Groq единственным провайдером.

## Команды из корня

| Команда | Назначение |
| --- | --- |
| `npm ci` | Установка зависимостей по lockfile. |
| `npm run app:start` | Запуск приложения. |
| `npm test` | Все тесты через `node --test test/*.test.js`. |

Сборка выполняет строгую проверку `app/scripts/validate-build-resources.js`. Для самостоятельного EXE нужны `app/resources/ffmpeg.exe` и `app/resources/ffprobe.exe`; проверка может скопировать их из `PATH`. Переменная `SHOTSHORTS_ALLOW_UNBUNDLED_FFMPEG=1` разрешает сборку без встроенных бинарников, но требует системный FFmpeg у пользователя. Перед пересборкой закройте приложение.

## Где проверять изменения

Тесты находятся в `test/` и используют встроенный Node.js test runner. Выбирайте проверки по затронутому поведению:

- Провайдеры и модели: `model-registry.test.js`, `groq-key-utils.test.js`, `groq-story-analyzer.test.js`.
- Транскрипт, субтитры и границы: `whisper-ass.test.js`, `story-chunker.test.js`, `story-padding.test.js`.
- Видео, баннеры и Cinema: `media-processor.test.js`, `banner.test.js`, `interstitial.test.js`, `cinema-bg.test.js`, `cinema-scene-detector.test.js`.
- Настройки, отмена и оценка времени: `settings-regressions.test.js`, `cancellation.test.js`, `eta-estimator.test.js`. Передача каждого готового клипа в очередь TikTok, включая отмену и ошибку последующего рендера: `process-generated.test.js`.
- TikTok API, OAuth, загрузка по частям, хранение токенов и защита от повторной отправки: `tiktok.test.js`. Интерфейс в изолированном Electron с имитацией TikTok: `node test/tiktok-ui-smoke.cjs`; реальный аккаунт и публикация этим сценарием не проверяются.
- Подстановка команд, нормализация и случайные выборки хештегов: `tiktok-captions.test.js`.
- Очередь и временные слоты: `tiktok-queue.test.js`. Обычный запуск браузера для ручного входа: `tiktok-login-browser.test.js`. Изоляция профилей, ожидание закрытия окна входа, определение аккаунтов и выбор сессии после перезапуска: `tiktok-studio-accounts.test.js`. Браузерное заполнение формы, проверка аккаунта и подтверждение результата на контролируемом макете без сетевых запросов к TikTok: `node test/tiktok-studio-smoke.cjs`. Реальная загрузка видео в форму и финальная постановка в расписание — разные проверки; отмечайте, какая из них выполнена.

Для изменений интерфейса дополнительно проверьте затронутый сценарий в Electron: загрузку и сохранение настроек, превью, запуск, прогресс, отмену или подтверждение сцен. Unit-тесты не доказывают корректность реального вызова AI или финального рендера с FFmpeg. Указывайте, какие проверки действительно выполнены.

## Сборка и релизы

Информационный сайт и правовые страницы находятся отдельно в `website/` и опубликованы на `https://shotshorts.vercel.app/` (Vercel, проект `shotshorts`). Страницы `/terms` и `/privacy` предназначены для полей регистрации приложения TikTok. У сайта нет фреймворка, сборки и пользовательской авторизации; публикуются только его статические файлы. Подробности и идентификаторы проекта описаны в `website/README.md`. Не отправляйте на этот хостинг настройки приложения, видео, токены или профиль Edge.

- `app/package.json` содержит конфигурацию electron-builder; результат помещается в `Ready_App_EXE/`.
- `build-portable.cmd` — корневой скрипт сборки для Windows.
- `.github/workflows/ci.yml` устанавливает зависимости и запускает `npm test`.
- `.github/workflows/release.yml` по тегу `v*` проверяет версии, запускает тесты, получает FFmpeg, собирает EXE и публикует релиз.
- Версия релиза должна совпадать в теге, корневом `package.json` и `app/package.json`; учитывайте `package-lock.json` при обновлении версии.
- `scripts/extract-release-notes.js` извлекает заметки из `CHANGELOG.md`; `scripts/repro-ci-build.ps1` предназначен для воспроизведения сборки CI.

## Правила сопровождения

1. Перед правкой изучите текущий `git status` и соответствующие модули. Пользовательские изменения и удаления сохраняйте.
2. Новые настройки проводите через схему и сохранение в `store.js`, интерфейс и конфигурацию обработки. Проверяйте совместимость существующих сохранённых настроек.
3. Сохраняйте отмену и передачу AbortSignal в длительных операциях, запросах и обработке FFmpeg.
4. Не помещайте API-ключи, пароли прокси и пользовательские медиа в документацию, логи или Git.
5. Не редактируйте зависимости в `node_modules/` и сгенерированные файлы в `Ready_App_EXE/`. Бинарники FFmpeg исключены из Git.
6. Не добавляйте отдельный веб-фреймворк для правок существующего Electron-интерфейса без требования задачи.
7. Обновляйте эту карту при изменении путей, архитектуры и команд. Поведение кода и npm-скрипты имеют приоритет над устаревшей документацией.

Эта папка содержит контекст конкретного проекта. Удалённый универсальный набор агентов, навыков и workflows не является частью этой карты.
