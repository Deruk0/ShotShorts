## Что делает приложение

ShotShorts берет длинное видео или аудио, извлекает речь через FFmpeg, делает полный транскрипт через **Whisper-совместимую модель**, отправляет текстовые блоки в **LLM-анализ** для поиска отдельных историй, а затем рендерит вертикальные клипы **1080x1920** с субтитрами и фоновыми видео.

Модели подключаются универсально через **Custom AI Models** в настройках: подходит любой OpenAI-совместимый провайдер (Groq, OpenAI, локальные серверы и т.д.). Провайдер хранит общий Base URL и API ключ, а модели привязываются к нему — один ключ покрывает сколько угодно моделей. Для транскрибации и анализа собираются **цепочки фолбэков**: если модель упёрлась в лимиты или недоступна, следующая в цепочке подхватывает работу автоматически.

## Быстрый старт

### Требования для запуска из исходников

- Windows 10/11 x64
- Node.js 20+
- FFmpeg в `PATH` или `app/resources/ffmpeg.exe`
- Хоть одна OpenAI-совместимая ИИ-модель (транскрибация) и модель для анализа

Для готового portable-приложения Node.js не нужен. Для плана публикаций TikTok Studio требуется установленный Microsoft Edge или Google Chrome.

### Установка

Готовый portable-`.exe` последней версии скачивается со [страницы Releases](https://github.com/Deruk0/ShotShorts/releases): файл `ShotShorts.2.2.1.exe` (GitHub заменяет пробелы на точки в именах файлов). Ничего устанавливать не нужно — FFmpeg уже внутри, достаточно запустить файл и настроить AI-модели в приложении. Каждый релиз назван по версии программы (`v2.2.1`, …) и содержит заметки из [CHANGELOG.md](CHANGELOG.md).

Или собери из исходников:

```bash
npm ci
```

### Запуск Electron-приложения

```bash
npm run app:start
```

### Сборка Windows `.exe`

Для сборки с локальными ресурсами нужны `ffmpeg.exe` и `ffprobe.exe` в `app/resources/`.
Prebuild-проверка попробует автоматически скопировать их из `PATH`; если FFmpeg не установлен в системе, build остановится до упаковки, чтобы не получить exe, который падает уже у пользователя.

```bash
npm run app:build
```

Команда создаёт portable-файл `Ready_App_EXE/ShotShorts <version>.exe`.
То же самое можно запустить двойным щелчком по `build-portable.cmd` в корне проекта или по `Ready_App_EXE/Создать_EXE.bat`. Перед пересборкой приложение нужно закрыть.

Для быстрой папочной сборки без упаковки в единый файл используй:

```bash
npm run app:build:dir
```

Она создаёт `Ready_App_EXE/win-unpacked/ShotShorts.exe`. Все файлы в `Ready_App_EXE/` являются артефактами сборки и не хранятся в Git.

Если сборка специально должна полагаться на системный FFmpeg, можно запустить её с `SHOTSHORTS_ALLOW_UNBUNDLED_FFMPEG=1`, но такой билд уже не будет самодостаточным.

### Релизы

Релизы собираются автоматически workflow-ом `.github/workflows/release.yml`: пуш тега `v*` (например `git tag v2.2.1 && git push origin v2.2.1`) запускает тесты, сборку portable `.exe` на Windows-раннере (FFmpeg докачивается в `app/resources/` автоматически) и публикацию GitHub Release с названием версии и заметками из `CHANGELOG.md`. Перед тегом нужно поднять версию в `package.json` и `app/package.json` — workflow сверяет их с тегом и падает при несовпадении.

## Использование

### Шаг 0. Подключи AI-модели

Без настроенных моделей генерация не запустится — приложение работает с любыми OpenAI-совместимыми провайдерами.

1. Открой вкладку **Settings → Custom AI Models**.
2. **Providers** — добавь провайдера: название, Base URL и API ключ. Например, для Groq укажи `https://api.groq.com/openai/v1` и ключ из [консоли Groq](https://console.groq.com/keys). Один провайдер = один ключ, к нему привязывается сколько угодно моделей.
3. **Models** — добавь модели, привязанные к провайдеру:
   - для транскрибации нужна Whisper-совместимая модель (endpoint `/audio/transcriptions`), например `whisper-large-v3`;
   - для анализа — любая чат-модель (Llama, GPT, Qwen и т.д.).
4. **Fallback chains** — собери цепочки для транскрибации и анализа: первая модель обрабатывает запрос, при rate limit или недоступности (429/401/403/404) автоматически подхватывает следующая. Порядок меняется стрелками ↑↓.
5. Выбери собранные цепочки в селекторах **Transcription** и **Analysis**.

### Шаг 1. Укажи пути

На вкладке **Generator**:

1. **Source Audio / Video** — исходное длинное видео или аудио (MP4, MP3, WAV и т.д.).
2. **Background Videos Folder** — папка с фоновыми вертикальными видео (ADHD-фон). Нужна для режима Stories, а также для режима Cinema с включённым СДВГ-роликом. Фоны берутся случайно, без повторов подряд.
3. **Output Folder** — папка, куда сохранятся готовые ролики.

### Шаг 2. Настрой субтитры и баннер (опционально)

- **Субтитры**: стиль (Classic, Minimal, Highlight, TikTok Bold, Heavy Shadow, Soft Box), шрифт, размер, регистр, количество слов в строке, караоке-подсветка. Позицию можно перетащить прямо в живом превью — фиксация по центру/краям работает автоматически.
- **Баннер**: фото или зацикленное видео поверх клипа; размер и позиция задаются drag-and-drop в превью. В режиме **Pause video & play banner with sound** ролик ставится на паузу каждые N секунд, проигрывается видео-баннер со своим звуком, затем контент продолжается с места паузы.
- **Зелёный хромакей баннера**: удаляет зелёный фон в превью и готовом видео Stories/Cinema, включая вставки с паузой. По умолчанию выключен; удаляет также зелёные детали внутри баннера.
- **СДВГ-ролик параллельно (режим Cinema)**: чекбокс «СДВГ-ролик параллельно» включает второй слой — отрывок фильма и случайные ролики из папки фонов идут рядом, каждый в своём прямоугольнике. Оба прямоугольника двигаются и растягиваются в живом превью (как баннер), можно выбрать порядок слоёв (что сверху) и заполнение пустого места: чёрный цвет, размытый кадр фильма или размытый СДВГ-кадр. Ролики сменяют друг друга и играют без звука; звук остаётся только у фильма.

### Шаг 3. Запусти генерацию

Нажми **Generate**. Дальше всё автоматически:

1. FFmpeg извлечёт и подготовит аудио (длинные записи нарезаются на чанки).
2. Whisper-модель сделает транскрипт с таймкодами по словам.
3. LLM найдёт отдельные законченные истории и привяжет их границы к паузам транскрипта.
4. Приложение отрендерит вертикальные клипы 1080x1920 с субтитрами и фоном.

Прогресс, ETA и статистику рендера видно в интерфейсе. Готовые клипы появятся в выбранной папке вывода, временные файлы удаляются сами.

### Публикация в TikTok

#### План публикаций через TikTok Studio

Готовые ролики из Stories и Cinema автоматически появляются в **TikTok → План публикаций** после рендера каждого клипа. Уже созданные ролики остаются в плане при отмене или ошибке дальнейшей генерации. План сохраняется между запусками приложения. Каждый ролик имеет отдельные дату и время, аккаунт, описание и хештеги, видимость, разрешение комментариев, повторного использования контента и маркировку ИИ.

1. Нажмите **Открыть TikTok Studio / войти** и войдите в нужный аккаунт в отдельном окне выбранного браузера. Для нового аккаунта доступны Microsoft Edge и Google Chrome; браузер сохраняется вместе с профилем. Этот способ использует браузерную форму TikTok и не требует ключей разработчика. После входа закройте все окна этого профиля и нажмите **Обновить аккаунты**. Пока ручное окно открыто, автоматизация этого профиля заблокирована.
2. Нажмите **Обновить аккаунты** и выберите аккаунт в **Настройках для новых роликов**. Для другого аккаунта используйте **Добавить аккаунт**: каждый вход хранится в отдельном профиле выбранного браузера. Проверка аккаунтов запускается кнопкой; возвращение фокуса в ShotShorts не открывает браузер. Укажите время первой публикации, интервал между роликами и общие параметры. Время отображается в часовом поясе компьютера; минуты и интервал должны быть кратны пяти.
3. Если нужна автоматическая загрузка сразу после обработки, включите соответствующую галочку и сохраните настройки **до генерации**. Новые готовые клипы получат последовательные временные слоты и будут загружаться заранее в расписание TikTok.
4. Для индивидуальных настроек оставьте автозагрузку выключенной. После обработки нажмите **Настроить** у нужного ролика, измените его время и параметры, затем сохраните. Подтвердите загрузку и нажмите **Загрузить настроенные ролики в TikTok**. Отправляются все настроенные записи со статусом черновика.
5. После подтверждённой постановки в расписание публикацию выполняет TikTok. До этого компьютер, интернет и ShotShorts нужны для передачи роликов и заполнения формы. Не закрывайте окно Edge во время загрузки.

В разделе **Пресеты описаний и хештегов** можно сохранить шаблоны текста и наборы тегов с минимальным и максимальным количеством. Команды описания: `{name}` — имя файла без расширения, `{filename}` — с расширением, `{n}` — номер в плане, `{hashtags}` — случайные уникальные хештеги из выбранного набора. Если `{hashtags}` отсутствует, теги добавляются в конец. Итоговое описание сохраняется один раз: обновление интерфейса, перезапуск и повторная отправка его не меняют. Для существующего черновика новый вариант нужно явно вставить и сохранить в редакторе. Изменение пресетов не переписывает готовые описания.

Приложение повторно проверяет выбранный аккаунт в Studio, читает обратно выбранные параметры и перед отправкой требует минимум 15 минут до публикации. Доступные даты и ограничения аккаунта определяет TikTok. В текущей форме Studio дуэты и сшивание объединены в настройку **Повторное использование контента**; для длинных видео она может быть недоступна. Если TikTok заблокировал её в выключенном состоянии, приложение продолжает отправку и показывает предупреждение у запланированного ролика. Настройки шаблона при этом сохраняются.

Кнопка **Сохранить и применить время ко всем черновикам** распределяет существующие черновики по первой дате и интервалу, пропуская занятые слоты. Описания, аккаунты и остальные настройки сохраняются. Автоматическое удаление карточек можно включить отдельно: оно применяется только после подтверждённой загрузки и сохраняет защиту от повторного добавления файлов.

Кнопка **Убрать из плана** удаляет только локальную запись. Видео на диске и публикация в TikTok сохраняются. Активно загружаемый ролик удалить нельзя.

После выбора файла приложение ожидает готовности видео и формы до 30 минут; перед отправкой отдельно ожидает активности кнопки планирования до 30 минут. Ролик считается запланированным только после проверки записи с нужной датой и временем в списке Studio, затем очередь переходит к следующему. При несовпадении аккаунта интерфейс показывает ожидаемый и обнаруженный логины.

При изменении интерфейса TikTok, входе, CAPTCHA, обрыве или неясном результате очередь останавливается. Откройте Studio и проверьте ролик: кнопка **Уже запланировано в TikTok** подтверждает результат локально; **Не запланировано — вернуть в план** разрешает настроить и отправить его повторно. После перезапуска незавершённые отправки не повторяются автоматически. Остановка очереди не отменяет публикации, уже запланированные в TikTok. Изменение общих настроек не переписывает существующий план.

Коммерческую маркировку текущий браузерный адаптер не настраивает: для рекламных роликов используйте отдельную форму Direct Post или TikTok Studio вручную. Файлы профиля Edge и `tiktok-queue.json` в каталоге данных приложения могут содержать приватные данные; не добавляйте их в Git.

#### Статистика TikTok

Выберите сохранённый аккаунт в разделе **Статистика TikTok** и нажмите **Обновить статистику**. Приложение показывает просмотры, лайки и комментарии для роликов на текущей странице списка Studio. Это не статистика всей истории канала. Снимок сохраняется с датой обновления; ошибка чтения не удаляет предыдущие данные. Если идёт отправка, статистика дождётся её завершения и откроется в отдельной временной вкладке.

#### Разовая немедленная публикация через API

Вкладка **TikTok** отправляет выбранное локальное видео напрямую через официальный Content Posting API (Direct Post). Можно выбрать готовый клип текущей генерации или файл MP4, MOV либо WebM, ввести описание и хештеги, выбрать видимость, разрешить или запретить комментарии, дуэты и сшивание. Перед каждой отправкой необходимо подтвердить публикацию. Доступны отметки контента, созданного ИИ, и коммерческого контента.

Для подключения нужны собственные учётные данные приложения из [TikTok for Developers](https://developers.tiktok.com/):

1. Зарегистрируйте приложение для платформы **Desktop** с **Login Kit** и **Content Posting API**, запросите разрешение `video.publish`.
2. В Login Kit зарегистрируйте Redirect URI `http://127.0.0.1:8902/callback/`.
3. Во вкладке TikTok откройте настройки интеграции, введите **Client key** и **Client secret**, нажмите **Сохранить интеграцию**. Не отправляйте секреты в чат и не добавляйте их в Git.
4. Нажмите **Подключить аккаунт** и разрешите доступ в браузере. После подключения приложение покажет аккаунт, доступные варианты видимости и ограничение длительности.
5. Выберите ролик, задайте описание и настройки, подтвердите согласие и нажмите **Опубликовать сейчас**. Снятая галочка «Разрешить комментарии» отключает комментарии к публикации.

**Публичная публикация требует аудита TikTok.** До аудита TikTok разрешает только приватные аккаунты и видимость «Только я»; наличие исходников или MCP не заменяет одобрение. TikTok не одобряет инструменты, предназначенные исключительно для личных аккаунтов или внутреннего использования командой. Перед подачей изучите [правила Content Posting API](https://developers.tiktok.com/docs/en/content-sharing-guidelines): одобрение не гарантируется.

Ключи и токены хранятся отдельно от обычных настроек, в зашифрованном файле `tiktok-credentials.enc` в каталоге данных Electron, с использованием защищённого хранилища ОС. Файл привязан к пользователю Windows. Client secret вводится владельцем интеграции локально; в EXE он не встраивается. Для распространения общей интеграции с единым Client secret нужен отдельный сервер авторизации — текущая реализация такого сервера не содержит.

Эта отдельная форма выполняет **немедленную публикацию через API**. Приложение показывает прогресс загрузки и опрашивает статус обработки. Идентификатор последней отправки сохраняется для проверки после перезапуска. Остановка загрузки не удаляет уже принятую TikTok публикацию. После обрыва сначала проверяйте статус; повторная отправка незавершённой публикации блокируется, чтобы не создавать дубликаты.

Проверка интерфейса с имитацией ответов TikTok и отдельным профилем Electron: `node test/tiktok-ui-smoke.cjs`. Она не обращается к TikTok и не публикует видео.

Проверка браузерного адаптера на контролируемой форме без отправки данных в TikTok: `node test/tiktok-studio-smoke.cjs`.

### Полезные настройки

- **App Language** — английский или русский интерфейс.
- **Presets** — быстрое переключение между сохранёнными наборами настроек.
- **Proxy** — HTTP/HTTPS/SOCKS5, если провайдер AI недоступен напрямую.

## Возможности

### AI и анализ

- Любые OpenAI-совместимые модели: транскрибация (Whisper-совместимый endpoint `/audio/transcriptions`) и чат-анализ
- Провайдеры с общим ключом: несколько моделей на один API ключ и Base URL
- Цепочки фолбэков для транскрибации и анализа: автоматическое переключение на следующую модель при rate limit или недоступности
- Двухэтапная проверка завязки и завершения каждой истории
- Привязка границ к блокам, словам и естественным паузам транскрипта
- Настраиваемая длина роликов в режиме историй: целевой диапазон (объединение коротких и нарезка длинных) и жёсткие границы (форс-слияние/нарезка крайних случаев); если безопасного разреза нет — история остаётся целиком
- Режим кино: длина сцены — только подсказка для ИИ (целевая/мин/макс), сильные сцены никогда не режутся; максимальное ограничение можно отключить полностью
- Режим кино: начала диалоговых сцен привязываются к визуальным склейкам фильма, action-сцены используют целевую длину из настроек и получают LLM-заголовки
- Экран ревью сцен в режиме кино: перед рендером можно исключить сцены или подвинуть их границы (с превью-кадрами и хуками); отключается настройкой «Просмотр сцен перед рендером»

### Субтитры

- Стили: Classic, Minimal, Highlight, TikTok Bold, Heavy Shadow, Soft Box
- Позиция: верх, центр, низ или свободное перетаскивание текста в живом превью с фиксацией по центру/краям
- Настройка шрифта, размера, регистра, отступа и количества слов в строке
- Караоке-режим с подсветкой слов
- Рендер через ASS/FFmpeg или Playwright overlay

### Видео

- Вертикальный формат 1080x1920
- H.264, 30fps
- Случайный ADHD-фон без повторов подряд
- Режим Cinema: СДВГ-ролик параллельно фильму — два прямоугольника со свободной раскладкой (перетаскивание и растягивание в превью), порядок слоёв и заполнение пустого места (чёрный / размытый кадр фильма / размытый СДВГ-кадр)
- Рекламный баннер: фото или зацикленное видео любого формата поверх клипа, позиция и размер через drag-and-drop превью
- Автоматический подбор и кеширование шрифтов
- Защита от зависания последнего кадра фонового видео

### Приложение

- Английский и русский интерфейс
- Пресеты настроек
- HTTP/HTTPS/SOCKS5 прокси
- Прогресс, ETA и статистика рендера
- Хранение настроек через `electron-store`

│       ├── store.js             # Настройки и статистика
│       └── cleanup.js           # Очистка временных файлов

Сгенерированные папки вроде `node_modules/`, `Ready_App_EXE/`, `app/dist/`, `dist/` и `build/` игнорируются Git.

## Проверки

```bash
npm test
npm run app:check-resources
```

`npm test` запускает все `test/*.test.js` через встроенный Node.js test runner. CI выполняет установку через `npm ci` и тесты на Node.js 22. Проверка ресурсов сообщает о наличии FFmpeg и FFprobe; перед сборкой выполняется строгая проверка.

Дополнительные сценарии интерфейса и браузерного адаптера:

```bash
node test/banner-ui-smoke.cjs
node test/tiktok-ui-smoke.cjs
node test/tiktok-studio-smoke.cjs
node test/tiktok-statistics-smoke.cjs
```

Эти сценарии используют изолированные данные и имитацию TikTok. Они не подтверждают реальную публикацию или работу внешних AI-провайдеров. Подробная карта проверок находится в [.agent/README.md](.agent/README.md).

## Безопасность

- Не коммить API ключи моделей, `.env` файлы, тестовые аудио и локальные сборки.
